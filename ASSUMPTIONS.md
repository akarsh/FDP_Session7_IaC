# Assumptions, unverified items and omissions

## Not tested (no Docker or Terraform in the build environment)
- The whole demo was never run end to end. Outputs on the backup slides are examples of the format, not captured runs.
- Tested locally with ansible-core 2.17.14: playbook syntax check; template task reports changed on first run, unchanged on an identical run, changed after editing the greeting; `creates:` with a glob skips correctly.
- Not tested: `terraform init/apply/destroy`, the docker provider 4.6.0 with `host = null`, the `TF_VAR_docker_host` override, `keep_locally = true` (no re-pull on rebuild), the Docker connection plugin, `apt-get` and nginx inside python:3.12-slim.
- Assumed (verify in the dry run): `apt-get update` leaves files matching `/var/lib/apt/lists/*Packages*`; nginx writes `/run/nginx.pid`; nginx may already start during install (then the start task is skipped and the first recap shows changed=3, not 4).
- Idempotence design: instead of the `apt` module (needs python3-apt, absent in this image) the playbook uses `command` with `creates:`, so an unchanged second run should report changed=0. This is by design but untested.
- Windows works only via WSL2 and is untested. macOS (Apple Silicon and Intel) and Linux are untested.

## Missing file
- `.terraform.lock.hcl` is not included: it can only be generated by `terraform init`. Run it once and keep the file in `demo/`.

## Version choices
- ansible-core pinned to 2.17.14 (the newest the build environment could install); newer releases exist. community.docker 5.4.0 (highest on Galaxy on 2026-11-06) was not checked for compatibility with 2.17.14. If `ansible-galaxy` complains, use a 4.x release.
- Image digest `sha256:4840d514...` is the multi-architecture index of python:3.12-slim read from Docker Hub on 2026-11-06 (includes amd64 and arm64). Newer builds of the tag exist later; the digest keeps results repeatable.
- Terraform 1.17.1 was the current version reported by HashiCorp's release check; the file requires >= 1.9.0.
